# Decision log

Decisions taken while the project lived in the old repository, and the decisions of the move on 18 November 2026. Each entry says what was decided, why, what was turned down, and where it was written down. `old-repo item N` is an issue or pull request in the old repository (see [MIGRATION.md](MIGRATION.md)); where the issue was moved, its new number is given too.

"Reason: not written down" means the source records the decision but no reason. Newest first within each group.

## Script Lab

**21 Nov 2026 - Script Lab: a sandbox inside PinglyMotion for testing RLV/LSL scripts written with Claude Code; not a full LSL IDE and no built-in script editor for now.** The scripts live in a repository on disk; Claude Code writes them; PinglyMotion runs them in a sandbox and shows restrictions, allowed and blocked actions, log and animations; Claude reads the same result through the control interface. It is its own track, separate from animation and UX, with eight steps in order (plan: [SCRIPT_LAB_PLAN.md](SCRIPT_LAB_PLAN.md)). Reasons: the project owner wants to build RLV tools with Claude Code and GitHub and test them quickly; an interpreter for the parts the scripts need is far smaller than a full LSL IDE. Limits: not full LSL, not all RLV behaviours, world effects (teleport, sitting, inventory) shown only as allowed or blocked. Rejected for now: a built-in script editor (the panel has an "Open in editor" button for the user's own editor), using flex or bison (the Windows CI would need new tools). Source: the project owner, 21 November 2026.

## Files and formats

**19 Nov 2026 – Easing choice stored as `curve` on the start key of a segment.** `.dingle` keys get an optional `curve` object, `{"type": "<name>"}`, with the six technical names of the easing choices (`linear`, `ease-in`, `ease-out`, `ease-in-out`, `ease-out-overshoot`, `constant`). It belongs to the start key of a segment and, when present, decides that segment alone; without it the two ease flags decide as before. Additive, no version bump; old files open and save byte for byte as before. An unknown or malformed `curve` gives Even (a straight line), never refuses the file, and counts as an ignored key so save warns. This replaces the earlier note that an unknown `curve.type` falls back to the plain ease flags: the job brief for #53 step 3 asked for Even. Reasons: one choice per pose change (proposal 2 in #53); an object leaves room for free curves (#11) as new types later; the start key holds it because each segment has exactly one start key. Source: #53 step 3, [DINGLE_FORMAT.md](DINGLE_FORMAT.md).

**20 Nov 2026 – Custom curve: one cubic Bezier per pose change, in a dialog next to the tiles.** First step of the curve editor (#11). A "Custom curve..." button next to the easing tiles opens a small dialog with the speed curve of the selected pose change and two round handles; OK stores it on the start key as `.dingle` `{"type": "bezier", "points": [x1, y1, x2, y2]}`, and picking a tile removes it. The handles are limited to x in [0, 1] and y in [-0.5, 1.5]; a curve that passes a key is cut at the joint's limits like Overshoot then settle; playback, the in-between frames on load and the `.anim` export use the same function. Kept out on purpose: per-joint choices, several handles, and any change to the timeline itself, which waits for the timeline redesign with the project owner (#14). The button is wired in the timeline view, not the main window, so this job did not touch the window file another job was changing. Reasons: one free shape that maps to common tools (CSS, After Effects) and needs only four numbers; the dialog keeps the beginner tile row unchanged. Source: #11, [DINGLE_FORMAT.md](DINGLE_FORMAT.md).

**18 Nov 2026 – `.dingle` layout: five decisions.** The project owner accepted all five proposals in #26. (1) Start now with ease flags only; the easing `curve` (#11) is added later without a version bump. (2) JSON, UTF-8, with the program's own emitter for byte-identical output; `QJsonDocument` only reads. (3) Key frames only are stored; in-between frames are computed on load, and a conversion test must show identical animations for the four bundled files before the program opens `.dingle`. (4) Saving an opened `.bvh` asks for a `.dingle` name and leaves the `.bvh` alone. (5) Only the four bundled QAvimator files are converted (originals kept in `tests/legacy-avm/`); `fuzz/corpus/avm` and `tools/legacy/TPose.avm` stay as AVM reader tests. Reasons: unknown keys are skipped by design, so later additions never break a reader; one truth per file; the AVM reader stays so old files open. Specification: [DINGLE_FORMAT.md](DINGLE_FORMAT.md). Source: #26.

**18 Nov 2026 – Own working format `.dingle`; no more AVM saving.** PinglyMotion gets a new working file format, `.dingle`, and never writes AVM again. Old `.avm` files still open and are saved as `.dingle` (the old file goes to the recycle bin only after the save succeeded). Default name for a new file: `pingle.dingle`. Bundled `.avm` files are converted. Built after the new parser (#9) and the easing editor (#11). Reason: AVM is QAvimator's format, not a standard, and only QAvimator and PinglyMotion read it; a working format is still needed because BVH loses key frames, easing, loop points and figure, and SL `.anim` is quantised and has no room for easing curves. Rejected: a versioned "AVM 2" (the earlier plan in old-repo item 118). Source: old-repo item 151 (now #26).

**18 Nov 2026 – Supported file formats and their order.** The project owner accepted the research recommendation: new parser and fuzzing (#9) → `.anim` export (#10) → `.anim` import (#22) → BVH from any skeleton with retargeting (#16) → glTF/GLB import (#12, with the small cgltf loader) → Blender, docs first (#13). Reasons: `.anim` is SL's own format (per-joint priority, ease, loop points, hand pose, emote) and only paid add-ons produce it today; retargeting is the core that glTF import needs too; glTF is open and Blender and many tools export it. Rejected or not now: **glTF export** (SL has no glTF animation upload); **FBX** (undocumented format; the open ufbx loader would fit the licence but is a large parser to carry and fuzz, and Blender already converts FBX to BVH or glTF for free; reconsider only on real demand); **Collada/DAE** (moved to legacy in Blender, no SL animation use); **Firestorm/Black Dragon pose XML** (importing someone else's animation as XML would get round its copy protection); **VMD, VRMA and other VTuber formats**; reading `.blend` files (not a stable exchange format). Mixamo: a warning in the docs only, no technical block, because its terms do not allow passing the raw files on. Source: old-repo item 118, comment on old-repo item 66 (now #13).

**15 Nov 2026 – New BVH/AVM parser and data model, with fuzzing, after the renderer.** Replace the inherited `BVH` parser and the unused `BvhParser`/`FileManager` with one parser that reads from memory, returns an error instead of crashing and has the safety limits built in, with fuzz targets from the start. Reasons: it removes the inherited code with the most security history (audit findings PM-01 to PM-07), gives a clean error path that can be tested without the GUI, and makes new formats easier. Less urgent than the renderer because old-repo item 25 had already made the old parser safe. Source: old-repo item 62 (now #9).

**15 Nov 2026 – SL `.anim` export, after renderer and parser.** Reasons: SL's own format with no conversion loss on upload, and clear SL-specific value over generic BVH tools. Known cost: the binary format must match the viewer exactly and needs tests against the viewer source and real uploads. Source: old-repo item 63 (now #10).

**15 Nov 2026 – Curve and easing editor later, together with `.anim` export.** Ideas may be taken from EffectCraft, but it is built in Qt. Reason: better motion quality that maps to `.anim` ease settings; not useful before `.anim` exists. Source: old-repo item 64 (now #11).

**15 Nov 2026 – glTF 2.0 import later, with a small single-file loader.** Reason: modern open format that Mixamo, Mesh2Motion and Blender export. Rejected: Assimp (see below). Source: old-repo item 65 (now #12).

**15 Nov 2026 – Blender round trip: relevant, later.** Reason: many SL creators use Blender; mostly a workflow and docs task. Source: old-repo item 66 (now #13).

## Technology

**19 Nov 2026 – Product direction: PinglyMotion continues as its own program.** After the comparison with Aurora Viewer's poser and animation editor (`docs/AURORA_STUDIO.md`), the project owner decided to go on with PinglyMotion as a stand-alone editor, and not to wait for any Aurora decision. Not chosen now: an own-named fork of Aurora with a studio mode, and moving features into Aurora as pull requests. Reason: not written down. The owner's wish is to keep working on his own program; nothing in the roadmap depended on the question. Source: #59.

**19 Nov 2026 – The Timeline panel is visible at every start.** Wish of the project owner after the timeline was off at every start in all Windows builds. Hiding it (Options > Show Timeline or the panel's close button) lasts for the current session only; the program no longer remembers it as off, and a saved panel layout cannot hide it either. Rejected: remembering the choice between starts. Source: pull request #120.

**18 Nov 2026 – Posing interface direction.** New users without animation background are the main target. Design ideas only from Aurora's poser and animation editor (Aurora is GPLv3, no code copied); data and logic may come from Firestorm's poser (LGPL 2.1). One camera and key scheme for everyone (a simple default, plus Blender and Second Life habits); the old QAvimator Shift/Alt/Ctrl joint keys are removed; floating panels that can be docked or popped out; English only for now with all text through `tr()`; no joint scale (BVH and `.anim` cannot store it). Rejected: rebuilding PinglyMotion on the Firestorm poser, which is tied to the whole viewer (#8 stands). Source: old-repo item 88 (now #14), `docs/POSING_UX.md` (old-repo item 135).

**18 Nov 2026 – Two work tracks side by side.** Posing (#14) and file formats (old-repo item 118) run in parallel, because they mostly change different files; one step at a time within a track, each tested on Windows. Replaces the numbered work order of 16 November. Source: old-repo item 137, `docs/PRODUCT.md`.

**18 Nov 2026 – Head and neck may bend -45..45 degrees forward and back.** Reason: in the Windows test of old-repo item 111 the project owner found the SL wiki values (-37..22) too tight; the new values come from a clinical range of motion source (AAOS). Source: old-repo items 129 and 156.

**17 Nov 2026 – New IK solver.** The inherited QAvimator IK solver was replaced by a damped least squares solver with warm start and a limit per update, and IK now solves for the value just set. Reason: the old solver threw arms and legs around when a goal could not be reached, and lagged one step behind the slider. Other options named in the issue (two-bone analytic IK, FABRIK, CCD) were not chosen. Source: old-repo items 127, 128 and 130.

**17 Nov 2026 – Joint limits follow the SL standard where one exists.** Classic joints use the SL wiki page "Suggested BVH Joint Rotation Limits"; finger bend and spread use the AAOS clinical range of motion; locked axes get ±5 degrees so the bundled poses stay inside the limits; other Bento bones keep their group limits. Reason: Second Life has no official table (`avatar_skeleton.xml` and the viewer have none, nor does the Firestorm poser), and the old QAvimator limits from about 2006 were never checked. Rejected: keeping the old QAvimator limits. Source: old-repo items 59 and 111.

**16 Nov 2026 – Replace libquat with Qt maths.** The IK code uses `QQuaternion`, `QVector3D` and `QMatrix4x4`; the old `libquat/` (Blender's MoTo maths from 2001–2005 and an uncompiled copy of TNT, about 12,000 lines) was removed. Reason: one maths library in the whole program, and IK gets tests. Source: old-repo items 97 and 112.

**16 Nov 2026 – Drop Qt 5.** Qt 6 only; the `linux-qt5` CI job was removed and deprecated Qt 6 calls were fixed. Reasons: Qt 5.15 open-source support has ended, nobody needs it for PinglyMotion (the Windows zip and AppImage use Qt 6), a clean build without deprecation warnings, and newer Qt APIs for the posing work. Accepted cost: Linux users with only Qt 5 packages can no longer build from source. Rejected: keeping Qt 5.15 as a fallback. Decided by the project owner. Source: old-repo items 98, 106 and 109.

**16 Nov 2026 – Posing before the parser.** Posing work comes before the new parser, on condition that the new parser keeps today's interface to the rest of the program. Reason: not written down. Source: old-repo item 101, `docs/PRODUCT.md`.

**15 Nov 2026 – Modernise in place; no rewrite and no new project.** Keep Qt 6 and C++ and replace the old parts one at a time, in the order renderer, parser and data model, `.anim` export. Reasons: it keeps what is hard and already correct (Bento skeleton generator, SL joint maths matching the viewer, bodies, tests, CI, security setup, remote control), each step can be tested on Windows before the next, and the old code sits in three places. Accepted cost: some legacy structure stays longer. Rejected: a rewrite or a new project. Source: old-repo item 60 (now #8).

**15 Nov 2026 – Renderer: OpenGL 3.3 Core.** Move from OpenGL 1.x fixed function to shaders with vertex buffers, GPU skinning and colour-ID picking, in small steps. Reasons: fixes slow hover picking and the cost of CPU skinning, allows better lighting, is supported wherever Qt runs, adds no dependency and drops the deprecated GLU. Accepted cost: needs a GPU with OpenGL 3.3 (roughly 2010 or newer). Done on 16 November; the old path was removed. Source: old-repo item 61.

**15 Nov 2026 – Rejected: Vulkan, DirectX 12, bgfx, OpenSceneGraph, Open3D.** Reasons: Vulkan is far more code for the same picture; DirectX 12 is Windows only; bgfx is an extra build dependency while OpenGL 3.3 is enough; OpenSceneGraph is old, heavy and built around fixed-function ideas; Open3D is for geometry and point clouds, not animation editing. Source: old-repo item 70.

**15 Nov 2026 – Rejected: Qt Quick 3D.** Reasons: it means rewriting the UI in QML (effectively a new project), gives less control over SL-exact skinning maths, and is harder to debug than an own small renderer. Source: old-repo item 69.

**15 Nov 2026 – Rejected: Assimp.** Reasons: a very large library with many file parsers, each one attack surface, and a long CVE history; only SL-relevant formats are needed, and glTF can be read with a small loader. Source: old-repo item 68.

**15 Nov 2026 – Not now: Eigen.** Reasons: Qt already has the maths types needed; an extra dependency without a current need. Reconsider for a more advanced IK solver. Source: old-repo item 67.

**15 Nov 2026 – ArtCraft (EffectCraft): ideas only, no code.** Its curve editor and timeline may inspire the design. Reasons for not using the code: it is Rust (would need a bridge to C++, more complex than the feature), very young, about 360,000 lines mostly written by AI agents, changes fast and is not reviewed. Source: old-repo item 71.

**15 Nov 2026 – Live link to Aurora over Aurora's LiveMesh.** The link uses LiveMesh (the link Aurora's Blender add-on uses), with a challenge answered by HMAC-SHA256 and a session key from a file only the user can read. Reason: the earlier separate link on its own port had security findings (any program could take the port or send poses). Rejected: the separate port. Source: old-repo items 11, 12, 13 and 78, `docs/LIVE_LINK_RESEARCH.md`.

**15 Nov 2026 – Bento body: Max, with the system avatar as fallback (replaced on 19 Nov 2026, see "Bodies").** The open source Max body (CC BY 4.0) is shown by default, so finger poses and facial expressions can be seen; the Linden system avatar stays as a fallback. Reason: the system avatar has mitten hands and its face is not weighted to the Bento bones. Source: old-repo items 42 and 46.

**15 Nov 2026 – Qt 6.12 LTS for the builds.** Windows and release builds moved from Qt 6.8.3 to 6.12.0 LTS. Reason: 6.8.3 has published CVEs, and newer 6.8 LTS patch releases are commercial only, so 6.12 is the way to get security fixes as open source. Source: old-repo items 18 and 58.

**15 Nov 2026 – Fuzzing scope.** Fuzz the prop files and the control API now, and BVH/AVM only with the new parser. Not fuzzed on purpose: `SL.lim` and `.llm` (read only from PinglyMotion's own data folder) and the old BVH/AVM parser (it will be replaced). Source: old-repo item 20.

## Bodies

**16 Nov 2026 – Ruth2 v4 planned as the default body; closed bodies not used.** The goal is to replace the Linden system avatar with the open source Ruth2 v4 body, keep Max as an option and add Roth2 v2 later; the work goes with posing. Reason: nobody in Second Life uses the system avatar any more and it looks dated. Closed bodies (Senra, eBody, Altamura, Viva) have no open licence and can only be used with written permission from their creators. Source: old-repo item 110 (now #15).

**19 Nov 2026 – The male figure shows Roth2 v2, chosen automatically from the figure type.** Decided by the project owner in chat. A male figure shows Roth2 v2 and a female figure shows the body chosen under Options > Body (Ruth2 or Max); there is no new menu entry and Options > Body stays as it is. Roth2 is male in shape already, so the male skeleton scaling is not applied to it. If `roth2.pmm` cannot be read, the male figure is the chosen body with the male skeleton scaling, as before. The nails of Roth2 are non-commercial and are not used. Credits and the AGPL notice for the mesh (head and UV map CC BY Linden Lab, rig parts CC BY 3.0) are in Help > About, the README and `bin/data/character/roth2/`. Rejected: a Roth2 entry in Options > Body. Source: issue #15, `docs/ROTH2.md`.

**19 Nov 2026 – The system avatar is removed; Ruth2 is the only standard body; its makers are credited.** Decided by the project owner in the discussion of issue #15. The Linden `.llm` meshes, their reader and the "system avatar" choice are gone; Max stays as an optional second body. Ruth2 is the default and the fallback (Max if Ruth2 cannot be read, and the other way round). A settings file that says "system" (or the old "Bento body" off) now gives Ruth2, without a message. The male figure had no male mesh for a while (Ruth2 with the male skeleton scaling); Roth2 v2 now gives it one, see the entry above. Credits for Ruth2 (makers, AGPL licence for the mesh as a separate data file, source link) are in Help > About, the README and `bin/data/character/ruth2/`. Rejected: keeping the system avatar until Roth2 is ready. Source: issue #15.

**19 Nov 2026 – Claude Desktop extension (`.mcpb`) first with the Python server (replaced, see the 21 Nov 2026 entry).** The MCP server is packaged as `PinglyMotion.mcpb` (built by a standard-library script, in the Windows zip and on releases, not signed).
