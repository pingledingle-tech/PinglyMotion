## Script Lab: folder, editor, converter (planned, 23 November 2026)

Status: A (definition check) is done; B (the folder is the object) is done in the core; F1 (the editor) is built; the rest is planned. It is the work of lane 1 (Script Lab). Order and wishes come from the project owner, 23 November 2026: "Lua er helt til slutt" (14:00); the plan goes into the goal picture with a docs job (14:11). The details of the folder model and the maker guide are in [SCRIPT_LAB.md](SCRIPT_LAB.md); the rules for the converter's output are in [SLUA_RULES.md](SLUA_RULES.md).

Decided: the converter starts with "LSL style" (what Linden Lab's `llcompat` layer allows) and is planned so that a Lua style can come later; the editor is built on our own text box (no QScintilla); the script checker stays inside PinglyMotion.

Order:

- **A. Definition check (done, lane 1 job L1-A).** Compares our function, constant and event lists with Linden Lab's definition files (`lsl-definitions`). It shows what we lack and replaces the hand-made gap lists: `python3 tools/lsl_definition_check.py`, report in [LSL_DEFINITION_CHECK.md](LSL_DEFINITION_CHECK.md), test `lsl_definition_check`.
- **B. The folder is the object (core done, lane 1 job L1-B).** A top folder is one object (one linkset), a subfolder is one prim, and the scripts and notecards of a prim sit in its folder. The whole folder runs as one linkset (`llMessageLinked` and `link_message` reach the other prims). Import checks all scripts at once. The event log and the limits show which script and which prim each line came from. Limits for path length, size, number of scripts and endless loops. Built in the core and for AI assistants (`lab_watch` with `"linkset": true`, [SCRIPT_LAB.md](SCRIPT_LAB.md), "The folder model"); the panel's Live page switches to it with the panel tree (D).
- **C. RLV type check.** Approved by the project owner: an invalid value is rejected as RLVa does, the command has no effect, and a clear warning says why. First confirm the behaviour against the RLVa code.
- **D. The panel (after B).** The Live page watches the folder as one object (the `linkset` mode of B). A tree with icons (a cube for the object, one shape per prim, a document for scripts, an LSL or Lua mark), colour dots and sums, memory per script, and the maker guide.
- **E. Props as prims (after B).** Props have no colour or transparency today (`src/prop.h`); they are needed if scripts change them.
- **F. The editor in our own text box, three jobs one after another.** F1 (built, lane 1 job F1, extended with the owner's list of 23 November 2026): editable text, syntax colours, undo that survives saving, save and run with a clear line, line numbers, Go to line, Find, auto-indent, bracket pairs, closing quotes, the Esc-then-Tab way out, the changed-outside question, starter help; Live never overwrites what the owner types ([SCRIPT_LAB.md](SCRIPT_LAB.md), "The editor"). F2 and F3 (built together in one pull request, lane 1 jobs F2 and F3, the project owner 23 November 2026, 16:45: «slå sammen små jobber som rører samme filer til én»): suggestions while typing and help text from Linden Lab's definition file, with a suggestion engine that the RLV job (R3) only adds a provider to; the language choice LSL or SLua, only the choice, behind a Lua switch in Setup that is off at start ([SCRIPT_LAB.md](SCRIPT_LAB.md), "Suggestions and help" and "The language choice").
- **G. Convert LSL to SLua, level 1 "LSL style".** A shared middle step sits between the LSL tree and the output, and the SLua details live in their own layer, so level 2 can swap that layer later. `jump` gets a marker and a panel warning: "this jump cannot be converted automatically, rewrite it by hand".

Last, not queued: a Luau trial build (MinGW is also not checked yet), convert level 2 (real Lua style) and Lua in the tool.

Not confirmed: that RLV works the same in SLua (to be tested last, in a Lua Beta region, in a viewer that has both RLV and Lua saving), and that Luau builds with MinGW.

Notes for the order: D, E and F touch the same file and run one after another. A change to a parser or the control commands needs a green fuzz run.
