## Script Lab: folder, editor, converter (planned, 23 November 2026)

Status: A (definition check) is done; B (the folder is the object) is done in the core; C (RLV type check) is done; F1, F2 and F3 (the editor, suggestions and the language choice) are built; R3 and R4 (the editor uses the RLV table, with exact tests) are built; D and E are done; G (convert to SLua, level 1) is built as a library; the example objects with guides (E1, [EXAMPLES.md](EXAMPLES.md)) are added, and Script Lab for beginners (U3: Make example project, the steps, selection between the tree and the 3D view, word tips; [UX_DECISIONS.md](UX_DECISIONS.md) 6o) is built; the rest is planned. It is the work of lane 1 (Script Lab). Order and wishes come from the project owner, 23 November 2026: "Lua er helt til slutt" (14:00); the plan goes into the goal picture with a docs job (14:11). The details of the folder model and the maker guide are in [SCRIPT_LAB.md](SCRIPT_LAB.md); the rules for the converter's output are in [SLUA_RULES.md](SLUA_RULES.md).

Decided: the converter starts with "LSL style" (the script keeps LSL's numbers inside; the converter writes `ll.` calls and changes positions, "not found" and booleans at the edge, and uses `llcompat` only for the functions removed from `ll`; [DECISIONS.md](DECISIONS.md), 23 Nov 2026) and is planned so that a Lua style can come later; the editor is built on our own text box (no QScintilla); the script checker stays inside PinglyMotion.

Order:

- **A. Definition check (done, lane 1 job L1-A).** Compares our function, constant and event lists with Linden Lab's definition files (`lsl-definitions`). It shows what we lack and replaces the hand-made gap lists: `python3 tools/lsl_definition_check.py`, report in [LSL_DEFINITION_CHECK.md](LSL_DEFINITION_CHECK.md), test `lsl_definition_check`.
- **B. The folder is the object (core done, lane 1 job L1-B).** A top folder is one object (one linkset), a subfolder is one prim, and the scripts and notecards of a prim sit in its folder. The whole folder runs as one linkset (`llMessageLinked` and `link_message` reach the other prims). Import checks all scripts at once. The event log and the limits show which script and which prim each line came from. Limits for path length, size, number of scripts and endless loops. Built in the core and for AI assistants (`lab_watch` with `"linkset": true`, [SCRIPT_LAB.md](SCRIPT_LAB.md), "The folder model"); the panel's Live page switches to it with the panel tree (D).
- **C. RLV type check (done, lane 1 job L1-C).** Approved by the project owner: an invalid value is rejected as RLVa does, the command has no effect, and a clear warning says why. Confirmed against the RLVa code; the value type is its own field in the behaviour table ([RLV_OPTION_TYPES.md](RLV_OPTION_TYPES.md)).
- **D. The panel (done, lane 1 job D+E).** The Live page watches the folder as one object (the `linkset` mode of B). A tree with icons (a box for the object, a square per prim, a document for scripts, "LSL script" as the mark; the Lua mark comes with Lua), colour dots and sums, memory per script, and the maker guide ([SCRIPT_LAB.md](SCRIPT_LAB.md), "The folder tree in the panel"). Left: `llGetLinkName` with the folder names.
- **E. Props as prims (done, lane 1 job D+E and job A1).** A prop named like a prim shows the colour and transparency its scripts give it, while the effects are shown ([SCRIPT_LAB.md](SCRIPT_LAB.md), "Props as prims"). Since job A1 (pull request 447) the props are made from the prims by themselves, a click on a prop is a touch, and a prop jumps where a script moves, scales or turns its prim ([SCRIPT_LAB.md](SCRIPT_LAB.md), "Props from prims, click as touch, moving props"). Since job A2 (pull request 448) a menu a script shows after the click stands as a box over the 3D view next to the click, and every row of "What the avatar may do" is an Allowed / Blocked choice that makes, runs and explains the RLV line ([SCRIPT_LAB.md](SCRIPT_LAB.md), "The menu box over the 3D view" and "Choose a restriction from the list"). Since job A3 (pull request 450) **Record what I do** saves the clicks, menu answers and RLV lines as a recipe in the object folder, and every save replays it and says in plain words what changed since last time; `lab_replay` runs it for an AI assistant ([SCRIPT_LAB.md](SCRIPT_LAB.md), "Record and replay"). Since job A4 (pull request 453) the part **Who talks to whom** shows every message of the last run as an arrow between boxes (the prims, you, your viewer, a web server), with its channel and text; a message nobody hears says why in words, a part that listens and passes on is marked as a hub, and a click on an arrow shows the line that sent it ([SCRIPT_LAB.md](SCRIPT_LAB.md), "The channel map").
- **F. The editor in our own text box, three jobs one after another (done).** F1 (built, lane 1 job F1, extended with the owner's list of 23 November 2026): editable text, syntax colours, undo that survives saving, save and run with a clear line, line numbers, Go to line, Find, auto-indent, bracket pairs, closing quotes, the Esc-then-Tab way out, the changed-outside question, starter help; Live never overwrites what the owner types ([SCRIPT_LAB.md](SCRIPT_LAB.md), "The editor"). F2 and F3 (built together in one pull request, lane 1 jobs F2 and F3, the project owner 23 November 2026, 16:45: «slå sammen små jobber som rører samme filer til én»): suggestions while typing and help text from Linden Lab's definition file, with a suggestion engine that the RLV job (R3) only adds a provider to; the language choice LSL or SLua, only the choice, behind a Lua switch in Setup that is off at start ([SCRIPT_LAB.md](SCRIPT_LAB.md), "Suggestions and help" and "The language choice").
- **R3 and R4. The editor uses the RLV table (built, one pull request, the project owner 23 November 2026, 15:36 and 16:47).** Suggestions after `@` inside `llOwnerSay` (commands, the forms after `=`, the options after `:` with their value type, the families with their ending), help per command (a plain sentence and an example in both modes, a dense line in Expert mode), one checked example per command, the warnings of job C in plain words with a fix in the editor and the problem list, a click that shows the code line, "RLVa only" marks while the viewer rule is RLV, and exact tests (R4) ([SCRIPT_LAB.md](SCRIPT_LAB.md), "RLV in the editor"). No Lua suggestions: Lua stays last.
- **G. Convert LSL to SLua, level 1 "LSL style" (built, lane 1 job G, the converter library and its tests; no panel yet).** A shared middle step (a small Lua tree and a Lua printer) sits between the LSL tree and the output, and the SLua details live in their own layer, so level 2 can swap that layer later. Warnings are data (line, plain message, fix) for the panel; `jump` gets a marker and the warning "This jump cannot be converted automatically; rewrite it by hand." Fuzzed in `fuzz_lsl`. Not tested in Second Life ([SLUA_RULES.md](SLUA_RULES.md), [SCRIPT_LAB.md](SCRIPT_LAB.md), "Convert LSL to SLua").

Last, not queued: a Luau trial build (MinGW is also not checked yet), convert level 2 (real Lua style) and Lua in the tool.

Not confirmed: that RLV works the same in SLua (to be tested last, in a Lua Beta region, in a viewer that has both RLV and Lua saving), and that Luau builds with MinGW.

Notes for the order: D, E and F touch the same file and run one after another. A change to a parser or the control commands needs a green fuzz run.
